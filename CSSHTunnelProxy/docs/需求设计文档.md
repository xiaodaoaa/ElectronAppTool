## 1. 项目概述

### 1.1 项目背景

用户需要通过 SSH 服务器建立加密隧道，将本地网络流量安全地转发至远程网络。本软件在本地启动 **SOCKS5** 和 **HTTP** 两种代理监听端口，所有经过代理的流量均通过 SSH 加密隧道传输，实现安全、灵活的代理上网或内网穿透能力。

### 1.2 项目目标

-   提供图形化桌面客户端，支持 SSH 隧道连接的创建、管理、监控；
-   本地同时监听 **SOCKS5 代理端口** 和 **HTTP 代理端口**；
-   支持密码认证、SSH 私钥认证（含带 Passphrase）；
-   支持连接保活、断线自动重连；
-   支持多隧道配置管理与持久化存储；
-   支持流量统计、连接日志查看；
-   支持开机自启、最小化到系统托盘。

### 1.3 目标用户

-   需要安全代理通道的开发者 / 运维人员；
-   需要内网穿透访问远程资源的用户；
-   偏好 Windows 桌面 GUI 操作的技术用户。

### 1.4 运行环境

| 项目       | 要求                                   |
| ---------- | -------------------------------------- |
| 操作系统   | Windows 10 / 11（x64、ARM64）          |
| 运行时     | .NET 10 Runtime                        |
| 框架       | WPF（Windows Presentation Foundation） |
| SSH 服务端 | OpenSSH 7.0+ / 兼容 SSH-2 协议的服务端 |

### 3.2 分层职责

| 层次                | 职责                         | 关键原则                          |
| ------------------- | ---------------------------- | --------------------------------- |
| **View 层**         | 界面渲染、用户交互           | 纯 XAML + 绑定，无业务逻辑        |
| **ViewModel 层**    | 数据绑定、命令、状态管理     | MVVM 模式，INotifyPropertyChanged |
| **Service 层**      | 业务编排、配置管理、生命周期 | 依赖注入，面向接口编程            |
| **Proxy Engine 层** | 协议解析、连接转发           | 协议与传输解耦，可独立测试        |
| **SSH 传输层**      | SSH 连接、加密通道           | 封装 SSH.NET，屏蔽底层细节        |

### 3.3 核心设计思路

>   **关键决策**：不直接使用 SSH.NET 的 `ForwardedPortDynamic`，而是**自建 SOCKS5/HTTP 协议解析层 + SSH direct-tcpip Channel 转发**。
>
>   **理由**：
>
>   1.  统一转发模型——SOCKS5 和 HTTP 代理共享同一个 `SshTunnelTransport`；
>   2.  可精确统计每条连接的流量与目标地址；
>   3.  可扩展规则分流（直连 vs 走隧道）；
>   4.  可支持本地认证（代理层面的用户名密码验证）。

### 4.2 SOCKS5 代理服务器（FR-03）

#### 4.2.1 功能描述

在本地指定端口启动 SOCKS5 代理服务器，接收客户端 SOCKS5 请求，解析目标地址后通过 SSH 隧道转发。

#### 4.2.2 协议支持范围

| SOCKS5 命令          | 支持情况 | 说明                       |
| -------------------- | -------- | -------------------------- |
| CONNECT (0x01)       | ✅ 支持   | TCP 连接转发（核心功能）   |
| BIND (0x02)          | ❌ 不支持 | 返回 Command Not Supported |
| UDP ASSOCIATE (0x03) | ⚠️ 预留   | 首期不支持，返回不支持     |

| 地址类型    | 支持情况 |
| ----------- | -------- |
| IPv4 (0x01) | ✅        |
| 域名 (0x03) | ✅        |
| IPv6 (0x04) | ✅        |

#### 4.2.3 认证

-   支持 `NO AUTH (0x00)` 和 `USERNAME/PASSWORD (0x02)` 两种认证方式；
-   由配置项 `EnableProxyAuth` 控制是否启用认证；
-   认证失败返回 `0x01`（general failure）并关闭连接。

#### 4.2.4 类设计

```
ISocks5Server
 ├── Socks5ProxyServer          // 监听与连接管理
 │    ├── AcceptLoop()          // 接受连接循环
 │    ├── HandleClientAsync()   // 处理单个客户端
 │    ├── ParseHandshake()      // 解析握手
 │    ├── ParseRequest()        // 解析 CONNECT 请求
 │    └── RelayData()           // 双向数据转发
 └── Socks5Protocol             // 协议常量与帧解析工具
```

### 4.3 HTTP 代理服务器（FR-04）

#### 4.3.1 功能描述

在本地指定端口启动 HTTP 代理服务器，支持两种工作模式：

| 模式                 | 说明                                     | 适用场景   |
| -------------------- | ---------------------------------------- | ---------- |
| **CONNECT 隧道模式** | 解析 CONNECT 请求后建立 TCP 隧道         | HTTPS 流量 |
| **普通转发模式**     | 解析 HTTP 请求，通过隧道转发到目标服务器 | HTTP 流量  |

#### 4.3.2 处理流程

**CONNECT 模式：**

1.  接收 `CONNECT host:port HTTP/1.1` 请求；
2.  解析目标地址与端口；
3.  通过 SSH 隧道建立到目标的连接；
4.  返回 `HTTP/1.1 200 Connection Established`；
5.  进入双向数据透传。

**普通 HTTP 模式：**

1.  接收完整 HTTP 请求头；
2.  从 `Host` 头或请求行 URI 提取目标地址；
3.  通过 SSH 隧道连接目标；
4.  转发请求头与请求体；
5.  回传响应（支持 chunked / keep-alive）。

#### 4.3.3 类设计

```
IHttpServer
 ├── HttpProxyServer
 │    ├── AcceptLoop()
 │    ├── HandleClientAsync()
 │    ├── ParseHttpRequest()     // 解析请求行与头部
 │    ├── HandleConnect()        // CONNECT 隧道
 │    ├── HandlePlainHttp()      // 普通 HTTP 转发
 │    └── RelayData()
 └── HttpParser                 // 轻量 HTTP 请求解析器
```

### 4.4 SSH 隧道传输核心（SshTunnelTransport）

#### 4.4.1 职责

作为代理引擎与 SSH 层之间的桥梁，为每个代理连接建立 SSH `direct-tcpip` Channel 并执行双向数据管道。

#### 4.4.2 核心接口

```csharp
public interface ISshTunnelTransport : IAsyncDisposable
{
    /// <summary>隧道连接状态</summary>
    TunnelState State { get; }

    /// <summary>建立 SSH 连接</summary>
    Task ConnectAsync(CancellationToken ct = default);

    /// <summary>断开 SSH 连接</summary>
    Task DisconnectAsync();

    /// <summary>
    /// 通过 SSH 隧道连接到目标地址，返回双向流。
    /// 内部通过 direct-tcpip channel 实现。
    /// </summary>
    Task<Stream> OpenChannelAsync(
        string targetHost,
        int targetPort,
        CancellationToken ct = default);

    /// <summary>流量统计事件</summary>
    event EventHandler<TrafficEventArgs> TrafficUpdated;

    /// <summary>连接状态变更事件</summary>
    event EventHandler<TunnelStateEventArgs> StateChanged;
}

public enum TunnelState
{
    Disconnected,
    Connecting,
    Connected,
    Reconnecting,
    Error
}
```

#### 4.4.3 数据管道

```csharp
/// <summary>
/// 双向流管道：将 clientStream 和 tunnelStream 双向桥接
/// </summary>
public static async Task RelayAsync(
    Stream clientStream,
    Stream tunnelStream,
    TrafficCounter counter,
    CancellationToken ct)
{
    var upstream = CopyAsync(clientStream, tunnelStream, counter, ct);
    var downstream = CopyAsync(tunnelStream, clientStream, counter, ct);
    await Task.WhenAny(upstream, downstream);
    // 任一方向结束则取消另一方向
}
```

#### 4.4.4 SSH.NET direct-tcpip 封装

SSH.NET 的 `SshClient` 未直接暴露 `direct-tcpip` Channel API，需通过以下方式实现：

**方案 A（推荐）**：利用 `SshClient.CreateForwardedPort` 的底层机制，通过反射或继承 `SshClient` 访问 `Session` 对象，调用 `Session.SendChannelOpenRequest` 打开 `direct-tcpip` Channel。

**方案 B（备选）**：对每个连接动态创建 `ForwardedPortLocal`，绑定临时本地端口后连接。性能略低但实现简单。

**方案 C（自研）**：基于 `System.Net.Sockets` 自行实现 SSH-2 协议层（工作量大，不推荐首期采用）。

>   📌 **首期采用方案 A**，封装为 `SshDirectTcpipChannel` 类；若遇到兼容性问题则回退方案 B。

#### 4.5.2 断线重连策略

```
断线检测
  ├── SSH Keep-Alive 超时（默认 30s 间隔，3 次无响应判定断线）
  ├── Socket 读写异常
  └── TCP 连接 Reset

重连策略
  ├── 指数退避：5s → 10s → 20s → 40s → 最大 60s
  ├── 最大重试次数：可配置（默认无限）
  ├── 重连期间代理端口保持监听，新连接排队等待（超时 30s 返回错误）
  └── 重连成功后自动恢复，无需重启代理服务
```

#### 4.5.3 保活机制

-   SSH 层：`SshClient.KeepAliveInterval = TimeSpan.FromSeconds(30)`
-   应用层：定时发送 `SSH_MSG_GLOBAL_REQUEST`（[keepalive@openssh.com](mailto:keepalive@openssh.com)）
-   可选：TCP Keep-Alive（`Socket.SetSocketOption`）

## 8. 安全设计

### 8.1 敏感信息保护

| 信息         | 保护措施                                     |
| ------------ | -------------------------------------------- |
| SSH 密码     | DPAPI 加密后存储，运行时解密到 SecureString  |
| SSH 私钥     | 文件权限校验 / 内嵌时 DPAPI 加密             |
| 代理认证密码 | DPAPI 加密                                   |
| 内存中的凭据 | 使用 `SecureString` 或 `Span<byte>` 及时清零 |

### 8.2 代理访问控制

-   默认监听 `127.0.0.1`，仅本机可访问；
-   可选监听 `0.0.0.0`（需用户显式确认安全风险）；
-   可选代理层用户名/密码认证（SOCKS5 USERNAME/PASSWORD、HTTP Proxy-Authorization）；
-   可配置允许的客户端 IP 白名单（预留）。

### 8.3 SSH 安全

-   强制 SSH-2 协议；
-   优先使用强加密算法：`aes256-gcm@openssh.com`、`chacha20-poly1305@openssh.com`；
-   支持 Host Key 验证（首次连接 TOFU 模式，后续严格校验）；
-   可选跳过 Host Key 校验（仅限用户显式配置，UI 警告）。

### 8.4 日志安全

-   连接日志不记录传输内容，仅记录元数据（地址、字节数、时间）；
-   日志文件权限限制为当前用户。

## 9. 异常处理与日志

### 9.1 异常分类与处理策略

| 异常类型         | 示例                 | 处理策略                         |
| ---------------- | -------------------- | -------------------------------- |
| SSH 连接失败     | 网络不通、认证失败   | 提示用户，记录日志，按策略重试   |
| SSH 连接中断     | 网络抖动、服务端断开 | 触发自动重连                     |
| 代理端口占用     | 端口被其他程序占用   | 提示用户更换端口                 |
| 目标连接失败     | 目标主机不可达       | 返回 SOCKS5 错误码 / HTTP 502    |
| 客户端断开       | 客户端主动关闭       | 清理 Channel，释放资源           |
| Channel 打开失败 | SSH 服务端拒绝转发   | 返回代理错误，记录日志           |
| 内存/资源泄漏    | 大量连接未释放       | 连接池 + 超时回收 + 定期 GC 检查 |

### 9.2 应用日志

-   框架：**Serilog** + 文件 Sink + UI 内存 Sink
-   日志级别：Verbose / Debug / Information / Warning / Error / Fatal
-   文件路径：`%APPDATA%\SSHTunnelProxy\logs\app-{date}.log`
-   滚动策略：按天滚动，保留 30 天，单文件 ≤ 50MB

### 9.3 资源清理

-   所有 `Stream`、`Socket`、`Channel` 均通过 `IAsyncDisposable` 管理；
-   隧道停止时：先停止代理监听 → 等待活跃连接优雅关闭（超时 5s）→ 关闭 SSH 连接 → 释放资源；
-   使用 `CancellationTokenSource` 级联取消。

## 14. 风险与应对

| 风险                                             | 影响 | 概率 | 应对措施                                                     |
| ------------------------------------------------ | ---- | ---- | ------------------------------------------------------------ |
| SSH.NET 不支持直接创建 direct-tcpip Channel      | 高   | 中   | 提前 PoC 验证；备选方案：动态 ForwardedPortLocal 或自研 SSH 层 |
| 高并发下端口/内存资源耗尽                        | 高   | 中   | 连接池 + 并发上限 + 资源回收机制                             |
| 不同 SSH 服务端兼容性差异                        | 中   | 中   | 多服务端测试矩阵；Host Key 验证容错                          |
| .NET 10 WPF 兼容性问题                           | 中   | 低   | 提前搭建项目骨架验证；关注 .NET 10 RC 变更                   |
| DPAPI 加密数据跨机器不可迁移                     | 低   | 高   | 文档说明；提供导出时明文选项（用户确认）                     |
| HTTP 普通转发模式复杂度高（chunked、keep-alive） | 中   | 中   | 首期优先 CONNECT 模式；普通转发作为增强迭代                  |
| 私钥格式兼容性（OpenSSH/PEM/PuTTY）              | 中   | 中   | SSH.NET 已支持多格式；补充 PuTTY ppk 转换工具                |
